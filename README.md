# AI Densitometry Quality Control

Сервис искусственного интеллекта для автоматизированной оценки качества
рентгеновских денситометрических исследований (DXA) и корректности разметки
анатомических структур.

## Назначение

Решение принимает на вход денситометрическое исследование в формате DICOM
и выполняет:

- определение анатомической области (поясничный отдел позвоночника /
  проксимальный отдел бедра);
- классификацию исследования как качественного или содержащего нарушение;
- оценку корректности укладки и позиционирования пациента;
- оценку корректности разметки анатомических структур и областей измерения;
- определение одного или нескольких типов нарушения качества;
- формирование структурированного отчёта в формате `.xlsx`.

Поддерживаемые анатомические области:

- **Поясничный отдел позвоночника** — корректная укладка (визуализация верхних
  краев подвздошных костей и половины тела позвонка Th12), выравнивание оси
  позвоночника (допустимый наклон до 5°), отсутствие посторонних предметов
  и артефактов.
- **Проксимальный отдел бедра** — правильное позиционирование (большой вертел,
  шейка бедра, седалищная кость), отсутствие ротации (оценка малого вертела),
  корректность области интереса (3 см сверху/снизу, 2 см по бокам),
  отсутствие посторонних предметов и артефактов.

## Основные возможности

- Пакетная обработка исследований из указанной папки.
- Автоматическое определение анатомической области с OOD-детекцией
  (отклонение нетипичных исследований).
- Сегментация анатомических структур и артефактов нейросетью
- Геометрический постпроцессинг: расчёт угла наклона оси позвоночника,
  определение ротации бедра, контроль области интереса.
- Формирование итогового отчёта xlsx.
- Визуализация: интерактивный просмотр или пакетное сохранение PNG.
- Docker + HTTP API для пакетной обработки.

## Сборка и запуск

# Системные требования

- Python 3.10+ или Docker.
- CPU достаточно. GPU опционально (CUDA 12.1).
- RAM ≥ 4 ГБ, диск ≥ 3 ГБ.

## Установка

Docker:

```
docker build -t dxa-ai-metrics:latest .
```

Локально:

```
chmod +x build.sh
./build.sh
```

`build.sh` создаёт `.venv`, ставит зависимости, делает скрипты исполняемыми, создаёт `config/`, `out/`, `visual_out/` и `config/input.txt`.

## Веса моделей

Веса лежат в репозитории, в папке `config/`:
- `cls.pt` — классификатор области;
- `unet_spine_mt_addDice.pt` — модель позвоночника;
- `hip_b0_v4.pt` — модель бедра.

Скачивать ничего не нужно. При запуске Docker веса монтируются с хоста через `-v`.

## Запуск

### Пакетная обработка

Docker:

```
docker run --rm --gpus all \
  -v "$(pwd)/config:/app/config:ro" \
  -v "$(pwd)/out:/app/out" \
  dxa-ai-metrics:latest batch
```

Локально:

```
./run.sh
```

Перед запуском указать путь к папке с DICOM в `config/input.txt`. Результат — `report.xlsx`.

### Визуализация

Docker (сохранение PNG):

```
docker run --rm --gpus all \
  -v "$(pwd)/config:/app/config:ro" \
  -v "$(pwd)/visual_out:/app/visual_out" \
  dxa-ai-metrics:latest visual --save /app/visual_out
```

Локально:

```
./run_visual.sh                    # интерактивный просмотр
./run_visual.sh save               # сохранить в visual_out/
./run_visual.sh save out/custom    # сохранить в свою папку
./run_visual.sh --save out         # то же самое
```

Управление в режиме просмотра: `A` — назад, `D` — вперёд, `Q` — выход.

### HTTP API

Docker:

```
docker run --rm --gpus all -p 8000:8000 \
  -v "$(pwd)/config:/app/config:ro" \
  -v "$(pwd)/out:/app/out" \
  dxa-ai-metrics:latest api
```

Локально:

```
python api.py
```

Эндпоинты:
- `GET /health` — статус.
- `POST /process` — принимает ZIP с DICOM, возвращает `report.xlsx`.

Пример:

```
curl http://localhost:8000/health
curl -X POST http://localhost:8000/process \
  -F "file=@study.zip" -o report.xlsx
```

### Через docker-compose

```
docker compose run --rm batch
docker compose run --rm visual
docker compose up api
```

## Формат входных данных

- DICOM (`.dcm`, `.dicom` или без расширения).
- Путь указывается в `config/input.txt`.

## Формат выходных данных

`report.xlsx`, одна строка — одно изображение.

| Колонка | Описание | Формат |
|---|---|---|
| path_to_study | путь к файлу | String |
| study_uid | StudyInstanceUID | String |
| image_uid | SOPInstanceUID | String |
| anatomical_region | область | String |
| quality_class | 0 — ок, 1 — нарушение | Integer |
| violation_type | типы нарушений через `;` | String |
| processing_status | Success / Failure | String |
| time_of_processing | секунды | Float |

## Модели

- **Классификатор области** — ResNet-18 + OOD (Mahalanobis, cosine, softmax).
- **Позвоночник** — U-Net (EfficientNet-B0), 4 класса (`background`, `spine`, `iliac`, `artifact`) + головы `ribs` (Th12 0/1), `artifacts` (0/1).
- **Бедро** — U-Net (EfficientNet-B0), 5 классов (`background`, `trochanter`, `neck`, `ischium`, `artifact`) + голова `artifacts`.

## Метрики

| Область | Точность min | mean | Ошибок |
|---|---|---|---|
| Позвоночник | 97.9% | 99.9% | 0 |
| Бедро | 97.7% | 99.8% | 0 |


## Скорость

| Этап | Время, с |
|---|---|
| DICOM decode | 0.003–0.004 |
| Препроцессинг | 0.002–0.004 |
| Классификатор области | 0.003–0.005 |
| OOD (Mahalanobis + cosine + softmax) | < 0.0001 |
| U-Net позвоночник | 0.012–0.035 |
| U-Net бедро | 0.010–0.030 |
| Постобработка маски | 0.003–0.008 |
| Геометрия (Cobb, ШДУ, ротация, ROI) | 0.002–0.005 |
| **Итого/кадр** | **0.013–0.027** |

Батч 8: ~0.026 с/кадр (~38 FPS).

Сегментаторы запускаются только после положительной классификации области. При отбросе кадра время обработки — только классификация, 0.006–0.012 с.

Загрузка весов при первом запуске: не более 15 секунд.

## Обучение

**Классификатор области**
- Backbone: ResNet-18 (ImageNet), заменённый FC, Dropout 0.5.
- Loss: кросс-энтропия + label smoothing 0.1.
- Оптимизатор: AdamW, cosine LR.
- Регуляризация: Mixup α=0.4, температура T=2.0.
- Разбиение: 70/15/15, стратифицированно, seed 42.

**Сегментаторы (U-Net + EfficientNet-B0)**
- Функция потерь:
  `L_seg = 0.4·L_CE + 0.4·L_Dice + 0.2·L_Focal`
  `L = λ_seg·L_seg + λ_ribs·L_ribs + λ_art·L_art`
- Веса: позвоночник — `λ_seg=0.7, λ_ribs=0.15, λ_art=0.15`;
  бедро — `λ_seg=0.75, λ_art=0.25`.
- Дисбаланс классов: взвешенная CE + `WeightedRandomSampler`
  (кадры с артефактами в батче в 3–4 раза чаще).
- Аугментации: flips (H/V), аффинные (сдвиг 5%, поворот ±15°),
  brightness/contrast ±20%, гауссов шум, elastic transform, coarse dropout.
- Нормализация: ImageNet.
- Разбиение: 70/15/15, стратифицированно по базовому UID исследования —
  кадры одного пациента не попадают одновременно в train и val/test.

**Дообучение под новую область**
- Заморозить энкодер EfficientNet-B0.
- Обучить декодер и выходной слой (K классов) + голову артефактов.
- Пересчитать OOD-статистики классификатора (μ, Σ, центроиды).

## Ограничения

- Обучен на двух областях. Для третьей — переобучение выходного слоя и пересчёт OOD-статистик.
- OOD оценивает по расстоянию до обучающего облака, а не по третьему классу.
- T=2.0 подобрана эмпирически.
- Пороги OOD пересчитываются при смене сканера или протокола.

## Известные ошибки

| Ситуация | Поведение |
|---|---|
| Папка не найдена | [ERROR], код 1 |
| DICOM битый | `processing_status = Failure` |
| OOD | `anatomical_region = "Не определена"`, `quality_class = 0` |
| Веса отсутствуют | исключение torch.load |
| Нет GPU | авто-переход на CPU |

## Руководство пользователя

1. `docker build -t dxa-ai-metrics:latest .` (или `./build.sh` локально).
2. Указать путь к DICOM в `config/input.txt`.
3. `docker run ... batch` (или `./run.sh`) → `report.xlsx`.
4. Для визуализации — `docker run ... visual --save /app/visual_out` (или `./run_visual.sh save out`).
5. Для API — `docker run ... api` (или `python api.py`).

## Развёртывание

3. `docker build` или `./build.sh`.
4. Проверить веса в `config/`.
5. Запустить нужный режим: batch / visual / api.
